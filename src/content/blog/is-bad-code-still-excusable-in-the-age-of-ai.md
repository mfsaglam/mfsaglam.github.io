We now have AI tools that can write code, refactor implementations, suggest architectural improvements, and generate tests in seconds.

So here's a question I've been thinking about:

**If we have all these tools at our fingertips, is writing bad code still excusable?**

In the past, we could argue that we didn't have enough time to refactor, explore alternatives, or write proper tests. Sometimes those were perfectly reasonable arguments.

But AI has significantly reduced the cost of doing these things.

We can ask it to identify unnecessary complexity, separate responsibilities, challenge our design decisions, or suggest better approaches.

So shouldn't we expect better code?

One might argue that if AI is writing and maintaining our code anyway, perhaps messy implementations aren't such a big problem anymore. After all, AI can navigate complex codebases and make changes much faster than we can.

But I don't think that changes the importance of good architecture.

**Software is constantly changing. And good architecture is what makes those changes easier, faster, and safer.**

The more tightly coupled and unnecessarily complex a system becomes, the harder it is to modify without affecting something else.

AI might be able to navigate that complexity faster, but the complexity itself still exists. Every change can introduce unexpected consequences, require additional verification, or make future changes more difficult.

That's why clean code and good architecture still matter, regardless of who's writing or maintaining the code.

Of course, good engineering doesn't mean introducing abstractions everywhere or designing for every imaginable future requirement. Sometimes the simplest implementation is exactly what we need.

What matters is keeping the system flexible enough to evolve without unnecessary friction.

And perhaps this is where our responsibility as engineers becomes even more important.

AI has made it easier than ever to produce code. But producing code was never the ultimate goal.

**The goal is to build software that can evolve.**

If AI has lowered the cost of writing, testing, and improving code, perhaps we should also raise our standards for what we're willing to accept.

Because AI hasn't eliminated the cost of bad architecture.

**It has simply given us fewer excuses for introducing it.**
